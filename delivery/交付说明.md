# 交付说明（IT 部门）

本目录包含两种交付形态的构建/部署脚本与文档。

## 目录结构

```
delivery/
├── 交付说明.md                    # 本文件（总览）
├── server/                        # 交付①：Web/服务端（Docker 镜像）
│   ├── Dockerfile                 # Debian 一体化镜像（前端 + 后端）
│   ├── docker-compose.yml         # 客户一键启动编排
│   ├── build-and-export.ps1       # 我方：构建并导出 wtcmd-web.tar
│   └── 部署说明.md                # 交给客户 IT 的部署文档
└── desktop/                       # 交付②：Windows 桌面端 + 授权签发工具
    ├── build-desktop-windows.ps1  # Windows 构建机上一键打包
    └── 打包说明.md                # 交给客户/管理员的打包文档
```

## 两种交付形态对比

| 项目 | 交付①：Web/服务端 | 交付②：Windows 桌面端 |
| --- | --- | --- |
| 形态 | Docker 镜像（`wtcmd-web.tar`） | Windows 安装包 + 授权签发工具 |
| 构建环境 | 任意装有 Docker 的机器 | **必须 Windows**（Python + Node） |
| 能否 Docker 化 | ✅ 是（Debian 容器） | ❌ 否（见下方说明） |
| 客户使用 | `docker load` + `docker compose up -d`，浏览器访问 | 运行安装包，本地桌面应用 |
| 授权 | Web 版不强制激活 | 3 天试用 + 授权码激活 |

## 关于「能否用 Docker 打包 Windows 桌面端」

**不能。** 桌面端内置后端用 PyInstaller 打包，PyInstaller **无法跨平台编译**——Linux 容器只能产出 Linux 可执行文件；Windows 桌面端需要 Windows 的 `.exe` 后端。electron-builder 能在 Linux 借助 Wine 产出 Windows 安装外壳，但内置后端仍是 Linux 程序，装到 Windows 上跑不起来。

> 「跨平台支持」（应用能在 Win/Linux **运行**）≠「跨平台编译」（在 Linux **构建出** Windows 产物）。

因此：

- **交付①**（Web/服务端）→ 用 Debian(Linux) 容器，标准 Docker 交付，见 `server/部署说明.md`。
- **交付②**（Windows 桌面端）→ 在 Windows 构建机上用一键脚本打包，见 `desktop/打包说明.md`。

## 我方操作速查

```powershell
# 交付①：构建并导出服务端镜像（在装有 Docker 的机器上）
.\delivery\server\build-and-export.ps1
# → 产出 delivery\server\wtcmd-web.tar，连同 docker-compose.yml、部署说明.md 一并交付

# 交付②：在 Windows 构建机上打包桌面端（+可选签发工具）
.\delivery\desktop\build-desktop-windows.ps1 -WithAdmin
# → 产出 release\desktop\windows\ 安装包、release\license-admin\windows\ 签发工具
```
