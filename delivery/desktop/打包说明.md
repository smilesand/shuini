# 桌面端打包与授权签发说明（交付②）

> 面向具备构建能力的 IT / 管理员。用于在 **Windows** 机器上打包桌面安装包，并（可选）构建管理员授权签发工具。

## 一、为什么桌面端不用 Docker 镜像交付

桌面端把后端用 **PyInstaller** 打包成内置可执行文件，而 **PyInstaller 不能跨平台编译**：在 Linux 容器里只能产出 Linux 可执行文件，无法产出 Windows 的 `.exe`。electron-builder 虽然能在 Linux 借助 Wine 产出 Windows 安装外壳，但里面的后端仍是 Linux 程序，装到 Windows 上无法运行。

**结论：Windows 桌面端必须在 Windows 环境打包。** 因此本项交付为「一键打包脚本 + 源代码」，在一台 Windows 构建机上执行即可，无需 Docker。

## 二、构建机环境要求（Windows）

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Windows | 10 / 11 或 Server | 打包与运行目标一致 |
| Python | 3.11+ | 加入 PATH，`python --version` 可用 |
| Node.js | 18+（LTS） | 含 npm，`node --version` 可用 |
| 网络 | 可访问 npm / electron 下载源 | 首次打包需下载 electron / NSIS 构建资源 |

## 三、打包步骤

将交付的源代码解压到构建机（例如 `D:\shuini_calculator`），在该目录打开 PowerShell：

```powershell
# 仅打包桌面安装包
.\delivery\desktop\build-desktop-windows.ps1

# 打包桌面安装包 + 管理员授权签发工具
.\delivery\desktop\build-desktop-windows.ps1 -WithAdmin
```

脚本会自动完成：

1. 用 PyInstaller 打包 Windows 后端可执行文件；
2. 构建桌面模式前端（`build:desktop`）；
3. 用 electron-builder 生成 NSIS 安装包。

## 四、产出物

| 内容 | 路径 |
| --- | --- |
| 桌面安装包（发给最终用户安装） | `release\desktop\windows\wtcmd-platform-desktop-*-win-x64.exe` |
| 管理员授权签发工具（可选，`-WithAdmin`） | `release\license-admin\windows\wtcmd-license-admin.exe` |

## 五、授权签发工具（管理员）

- `wtcmd-license-admin.exe` 是带图形界面的授权管理程序：管理被授权设备信息，并为设备指纹签发授权码。
- 双击运行，按界面提示：读取设备码 → 录入使用人/有效期 → 签发授权码 → 交付给对应设备激活。
- **安全须知：**
  - 该工具**内嵌授权私钥**，任何持有者都能签发合法授权码。
  - 仅限授权方管理员在受控机器上使用，**切勿随桌面安装包一起分发给最终用户**。
  - 构建该工具需要 `scripts/keys/` 下的密钥；若源码包未包含密钥，请先执行 `python scripts/init_license_keys.py` 生成（生成后请妥善保管私钥）。

## 六、桌面端使用与激活流程（最终用户）

1. 运行安装包 `wtcmd-platform-desktop-*-win-x64.exe`，按向导安装。
2. 首次启动为 3 天试用；试用到期后进入激活页。
3. 用户将界面显示的**设备码**提供给管理员。
4. 管理员用签发工具生成**授权码**回传，用户在激活页粘贴授权码完成激活。

## 七、常见问题

| 现象 | 处理 |
| --- | --- |
| 提示缺少 python / node | 安装并加入 PATH 后重开 PowerShell 再试 |
| electron-builder 下载缓慢/失败 | 检查网络；可配置 npm / electron 镜像源后重试 |
| 找不到签发工具的私钥 | 先运行 `python scripts/init_license_keys.py` 生成密钥与签发工具 |
| 安装包运行后后端不启动 | 确认是在 Windows 上打包（非 Linux 交叉编译产物） |
