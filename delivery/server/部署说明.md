# 混凝土配合比设计系统 · Web/服务端 部署说明（交付①）

> 面向客户 IT 技术部门。本包为「前端 + 后端」一体化 Docker 镜像，导入后一条命令即可启动，浏览器访问即可使用。

## 一、交付内容

| 文件 | 说明 |
| --- | --- |
| `wtcmd-web.tar` | Docker 镜像离线包（含前端页面 + 后端服务） |
| `docker-compose.yml` | 一键启动编排文件 |
| `部署说明.md` | 本文档 |

## 二、环境要求

- 一台 Linux 服务器（推荐 Debian / Ubuntu，x86_64）。
- 已安装 **Docker**（20.10+）与 **Docker Compose 插件**（`docker compose` 命令）。
  - 验证：`docker version` 与 `docker compose version` 均能正常输出。
- 开放对外访问端口（默认 `8000`，可在编排文件中改为 `80` 等）。

## 三、部署步骤

将三个交付文件放到服务器同一目录（例如 `/opt/wtcmd`），然后：

```bash
cd /opt/wtcmd

# 1) 导入镜像（首次或每次更新镜像时执行）
docker load -i wtcmd-web.tar

# 2) 启动（后台常驻，开机自启）
docker compose up -d

# 3) 查看运行状态与日志
docker compose ps
docker compose logs -f
```

启动完成后，浏览器访问：

```
http://<服务器IP>:8000
```

- 默认管理员账号：**admin**，默认密码：**123456**
- **首次登录后请立即在「个人中心」修改密码。**

## 四、常用运维命令

```bash
docker compose stop        # 停止（保留数据）
docker compose start       # 再次启动
docker compose down        # 停止并移除容器（数据卷保留，不丢数据）
docker compose restart     # 重启
docker compose logs -f     # 实时日志
```

## 五、数据持久化与备份

- 所有业务数据（加密 SQLite 数据库）与日志保存在 Docker 数据卷 **`wtcmd-data`**（容器内路径 `/data`）。
- 升级镜像（重新 `docker load` 后 `docker compose up -d`）**不会丢失数据**。
- 备份数据卷：

  ```bash
  docker run --rm -v wtcmd-data:/data -v "$PWD":/backup debian:bookworm-slim \
    tar czf /backup/wtcmd-data-backup.tar.gz -C /data .
  ```

- 恢复数据卷：

  ```bash
  docker run --rm -v wtcmd-data:/data -v "$PWD":/backup debian:bookworm-slim \
    tar xzf /backup/wtcmd-data-backup.tar.gz -C /data
  ```

## 六、可选配置

在 `docker-compose.yml` 中可调整：

| 配置 | 说明 |
| --- | --- |
| `ports: "8000:8000"` | 改为 `"80:8000"` 即可用 80 端口对外 |
| `SC_ADMIN_USERNAME` / `SC_ADMIN_PASSWORD` | 自定义初始管理员账号口令（**仅首次初始化数据库时生效**） |
| `TZ` | 容器时区，默认 `Asia/Shanghai` |

> 前端已内置为「同源访问」（请求发往当前访问的主机 `:端口/api`），因此无论部署在哪台服务器、哪个端口，都无需修改任何接口地址。

## 七、升级流程

1. 收到新的 `wtcmd-web.tar`。
2. `docker load -i wtcmd-web.tar`
3. `docker compose up -d`（自动用新镜像重建容器，数据卷不变）。

## 八、常见问题

| 现象 | 处理 |
| --- | --- |
| 访问 8000 无响应 | 确认容器 `docker compose ps` 为 running；确认服务器防火墙/安全组放行端口 |
| 端口被占用 | 修改编排文件左侧宿主机端口，如 `"8080:8000"` |
| 忘记管理员密码 | 由其他管理员在「用户管理」中重置；若全部遗失，请联系我方 |
| 需要 HTTPS | 建议在容器前加 Nginx / 反向代理终止 TLS，并转发到 `127.0.0.1:8000` |
